### 第二次反转：她贴出 `round_full2.csv`（120 行 = subagent 60 + teams 60，无 single）

**新发现：库里的 token 不只"漏"，还在"重复算"。**
`tracer.log_turn` 的调用点在 `loop.py:337`，位于 `for tc in tool_calls` 循环**内部** ——
一轮调 N 个工具就写 N 行，每行都带**同一个 usage**。`finish_run` 的 `SUM(prompt_tokens)`
于是把这一轮的用量算了 N 次。
（`n_turns` 用的是 `COUNT(DISTINCT turn)` → **轮次是准的，只有 token 虚高**。
 虚高倍数 = 工具调用数/轮数：single 1.67× · subagent 1.44× · teams 1.82×）

**实测证据（2026-09-15 复核）**：
- `subagent/A01`：4 行 4 轮，每轮 1 工具 → `runs=9012 = 去重=9012 = CSV=9012`，三方一致
- `single/B03`：14 行 7 轮（turn1 两行同为 1158，turn6 三行同为 9262）
  → `runs 88,340` vs 去重 `45,081`
- 全量：CSV 120 行减「主 agent 去重」，**无一行负数**，其中 **25 行严格等于 0**
  （全部是 subagent 未触发 spawn 的运行，含 A06/C07 等多工具调用轮）→ 拆分自洽
